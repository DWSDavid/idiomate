## Design principles for this version
- **Less is more.** No feature clutter. Each addition must earn its place.
- **On-demand, cached.** Deep dive data is generated by LLM only when the user requests it, then stored permanently in the DB. Never regenerate unless forced.
- **Cross-reference the user's own list.** When showing word family or near-synonyms, always check whether the user already owns those words and highlight them. This turns isolated captures into a connected vocabulary network.

## Workstream S1 — DB + brain: Word Deep Dive data layer

**Goal:** Store word family, near-synonyms, and usage examples per vocab item; generate on demand via LLM.

```sql
ALTER TABLE vocab ADD COLUMN near_synonyms TEXT;
```
Use `ensureColumn(db, 'vocab', 'word_family', 'TEXT')` and the same for `near_synonyms`, matching the existing pattern exactly.

### 1b. Shared types
In `shared/types.ts`, add to the `Vocab` interface:
```ts

nearSynonyms?: Array<{ word: string; distinction: string }>;
```

### 1c. Zod schema
In `server/src/brain/schema.ts`, add:
```ts
export const nearSynonymZ = z.object({
  word: z.string().min(1),
  distinction: z.string().min(1),
});

export const wordDeepDiveZ = z.object({
  wordFamily: z.array(z.string().min(1)).min(1).max(12),
  nearSynonyms: z.array(nearSynonymZ).max(4),
  usageExamples: z.array(z.string().min(1)).min(1).max(3),
});

export type WordDeepDive = z.infer<typeof wordDeepDiveZ>;
```

### 1d. Brain function
In `server/src/brain/enrich.ts`, add:
```ts
export async function deepDiveWord(
  provider: LLMProvider,
  word: string,
  model: string,
): Promise<WordDeepDive>
```

System prompt:
```
You are a vocabulary analyst for a professional English writing assistant.
Return ONLY JSON. Every field is a string (or array of strings) when present; never use booleans.
Shape: { wordFamily, nearSynonyms, usageExamples }
- wordFamily: all common inflected and derived forms (e.g. for "falter": ["falters","faltered","faltering","falteringly"]). Include the base form. Max 12.
- nearSynonyms: up to 4 near-synonyms each with a one-sentence "distinction" explaining when to prefer one over the other in professional writing. Be specific about register, formality, and domain.
- usageExamples: 3 short, natural sentences in finance, tech, or professional writing contexts. Each sentence must use the word or one of its family forms naturally.
```

User prompt: `Word: ${word}`

Parse with `wordDeepDiveZ.parse(JSON.parse(raw))`. Follow the same `.catch` tolerance pattern as `enrichedVocabZ` for any optional fields.

### 1e. DAL — store and retrieve deep dive
In `server/src/db/dal.ts`, add:

```ts
export function saveDeepDive(
  db: Database.Database,
  userId: string,
  vocabId: number,
  dive: WordDeepDive,
): void
// UPDATE vocab SET word_family = ?, near_synonyms = ? WHERE id = ? AND user_id = ?
// Store as JSON.stringify; word_family and near_synonyms separate columns.

export function getDeepDive(
  db: Database.Database,
  userId: string,
  vocabId: number,
): WordDeepDive & { usageExamples: string[] } | null
// SELECT word_family, near_synonyms, examples FROM vocab WHERE id = ? AND user_id = ?
// Return null if word_family is null (not yet generated).
// usageExamples come from the existing `examples` column (already stored at capture time).
// word_family and near_synonyms are parsed from JSON.
```

Also update `mapVocab` in `dal.ts` to include `wordFamily` and `nearSynonyms` parsed from their columns.

### 1f. API endpoint — on-demand, cached
In `server/src/routes/vocab.ts`, add:
```
GET /api/vocab/:id/deep-dive
```
Logic:
1. Parse `:id` as integer; 404 if not a number.
2. Look up the vocab row — 404 if it doesn't belong to `req.userId`.
3. Call `getDeepDive(deps.db, req.userId, id)`.
4. If cached (not null): return it immediately — no LLM call.
5. If not cached: call `deepDiveWord(deps.utilityProvider, vocab.word, config.modelUtility)`, then `saveDeepDive(...)`, then return the result.
6. Also include a `relatedInYourList` field in the response:
   ```ts
   relatedInYourList: string[]  // words from wordFamily + nearSynonyms[].word that exist in the user's vocab (by normalized match)
   ```
   Do this with a single SQL query: `SELECT word FROM vocab WHERE user_id = ? AND normalized IN (?)` against the union of family + synonym words, normalized.

Response shape:
```ts
{
  wordFamily: string[];
  nearSynonyms: Array<{ word: string; distinction: string }>;
  usageExamples: string[];
  relatedInYourList: string[];
}
```

### 1g. Client API
In `client/src/api.ts`, add:
```ts
export interface WordDeepDiveResponse {
  wordFamily: string[];
  nearSynonyms: Array<{ word: string; distinction: string }>;

}
export function getWordDeepDive(id: number): Promise<WordDeepDiveResponse>
```
`GET /api/vocab/${id}/deep-dive`.
