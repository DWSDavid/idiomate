# Idiomate v1.1 Implementation Plan

> Builds on the MVP. Driven by real-use feedback. REQUIRED: TDD, exact paths, commit per task. **Claude authors `rules.ts` (done) and reviews each phase; Codex implements backend; the UI redesign uses the `design-taste-frontend` skill.**

**Goal:** Make Idiomate feel relevant and genuinely teach — live news-driven prompts, topic-fit vocab priming (10), deeper named-rule coaching with a highlighted native version, a profile that updates, and a redesigned UI.

---

## Workstream A — Live news daily prompts (kills local bank)

**Files:** Create `server/src/news.ts`; modify `server/src/routes/prompts.ts`, `server/src/brain/prompts.ts`, `server/tests/news.test.ts`.

- Topic rotation: `['private equity','humanoid robotics','artificial intelligence','financial markets','geopolitics','technology policy']` (extendable).
- `fetchHeadlines(topic, fetchImpl?)`: GET `https://news.google.com/rss/search?q=<encoded topic>&hl=en-US&gl=US&ceid=US:en`, parse `<title>` tags (skip the feed's own title), return top ~6 headline strings. No API key. Network is best-effort.
- `assembleNewsPrompt({topic, headlines})` (in `brain/prompts.ts`): system instructs a single discussion-style prompt ("What's your view on …?") aimed at **academic writing + professional discussion prep**, grounded in the headlines, inviting a paragraph-length argument (not a list). Returns `{theme,text}` via `dailyPromptZ`.
- `GET /api/prompt/today`: pick today's rotated topic → `fetchHeadlines` → `generate via utility model` → cache in `prompts` table keyed by date. **Fallback** to LLM-only generation if fetch fails or returns nothing. Remove the static local bank as the primary path (a tiny hardcoded fallback prompt is fine for total offline failure).
- Test: with a stub `fetchImpl` returning fake headlines + a mock provider, assert the generated prompt is non-empty and the request to the model includes the headlines.

**TDD note:** keep `fetchHeadlines` injectable (`fetchImpl?: typeof fetch`) so tests never hit the network.

## Workstream B — Vocab priming overhaul (topic-fit, 10, new+old blend)

**Files:** `server/src/db/dal.ts`, `server/src/routes/vocab.ts`, `server/src/brain/prompts.ts`, `client/src/api.ts`, `client/src/components/VocabPrime.tsx`, tests.

- **Candidate pool, blended (DAL):** add `getPrimeCandidatePool(db, n=40)` = union of:
  - top ~25 by the existing priority score (recent/frequent/phrase-weighted), and
  - ~15 *oldest unused* (`WHERE times_used = 0 ORDER BY last_captured ASC`), deduped by `normalized`.
  This guarantees a **new + old** mix for memory while the LLM picks for fit.
- **Topic-fit selection (LLM):** wire the existing `selectPrimeWords` into `/api/vocab/prime`. Pass the **full prompt text** (not just `theme`) as `topic`, plus the blended pool; instruct the model to pick **10** best-fit terms, **favoring phrases/collocations** and terms useful for academic/professional writing. Time is a secondary signal — relevance to the prompt wins.
- `/api/vocab/prime?promptText=...&limit=10`: build pool → `selectPrimeWords` → resolve back to the chosen `Vocab` rows → `incrementVocabSuggested` on the chosen → return them.
- Client: `primeVocab` default `limit=10`; `VocabPrime` takes the **prompt text** (App passes `prompt?.text`), not just theme. Render up to 10 chips.
- Update `assemblePrimePrompt` to request 10 and to state the academic/professional-writing bias; widen `primeWordsZ` max to 10.

## Workstream C — Deeper coaching: named rules + native version (the core)

**Files:** `shared/types.ts`, `server/src/brain/schema.ts`, `server/src/brain/prompts.ts`, `server/src/brain/coach.ts`, `server/src/routes/sessions.ts`, `client/src/components/CompareView.tsx`, tests.

1. **Schema (shared/types.ts):** extend `Annotation` with:
   ```ts
   rule?: string;                         // named principle, e.g. "Let's + base verb"
   ruleExample?: { before: string; after: string };
   ```
   Extend `CoachResponse` with:
   ```ts
   nativeVersion?: string;                // a fully-corrected, natural rewrite of the paragraph
   ```
2. **zod (`schema.ts`):** add `rule`, `ruleExample` (optional) to `annotationZ`; add `nativeVersion: z.string().optional()` to `coachResponseZ`.
3. **Prompt (`prompts.ts` `assembleCoachPrompt`):** inject `rulesSnippet(rulesForTypes([...topErrors]))` (fall back to the full `rulesSnippet()` when topErrors is sparse) from `./rules.js`. Instruct the model, per issue, to set:
   - `errorType` (taxonomy), `rule` (the most specific named principle), a one-line `explanation` (the why), `ruleExample` (a short illustration), `hint` (no leak), and `modelRewrite`.
   - Also produce `nativeVersion`: the whole paragraph rewritten to read naturally (native), so the user can compare. Keep `modelRewrite`/`nativeVersion` hidden by the UI until the user submits their own rewrite (reveal-gate unchanged).
4. **sessions route:** accept and persist the new annotation fields (store `rule` in `annotations` table — add columns `rule TEXT`, `rule_example TEXT`). Migration: `ALTER TABLE annotations ADD COLUMN ...` guarded by existence check, or recreate in `schema.sql` (dev DB is disposable).
5. **CompareView UI:** after submit, show three things stacked:
   - **Native version** with **inline highlights** of what changed (diff the user's rewrite vs `nativeVersion` — word-level diff; highlight insertions/changes).
   - Per issue: `errorType` chip + **rule name** + `explanation` (why) + `ruleExample` (before→after).
   - The user's rewrite and the original, for reference.
6. Test (`coach.test.ts`): mock returns `rule`, `ruleExample`, `nativeVersion`; assert they survive zod and that `hint !== modelRewrite`.

## Workstream D — Profile updates after submit (bug fix)

**Files:** `client/src/App.tsx`, `client/src/components/ProfileDashboard.tsx`.

- Root cause: `ProfileDashboard` fetches `/api/profile` once on mount; nothing refetches after **Save Session**.
- Fix: lift a `refreshKey` (number) in `App`; increment it in `handleSubmitSession` on success; pass to `ProfileDashboard` (e.g. `useEffect(..., [refreshKey])`) so it refetches. Show updated tallies + activation immediately.
- Also surface a clear "Session saved — profile updated" state.

## Workstream E — UI redesign with `design-taste-frontend`

**Runs after C lands** (so the new fields exist to design around). Use the **`design-taste-frontend` skill**. Brief: a calm, editorial, focused writing tool — not a dashboard. Single-column writing flow; the coach feedback should feel like a thoughtful editor's margin notes; native-version highlights legible; vocab primes as quiet chips; profile as a small, glanceable strip. Keep it local/fast, no heavy frameworks beyond Tailwind. Respect the reveal-gate (no fix visible pre-submit).
