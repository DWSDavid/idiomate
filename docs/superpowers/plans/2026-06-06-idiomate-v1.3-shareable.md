## S2 - Per-user data isolation (the heavy one)

**Goal:** each peer has their own writing/errors/vocab. No accounts; a lightweight identity.

**Identity:** client generates a UUID on first load (localStorage `idiomate_uid`) and the user enters a display name. Every `/api` request sends `x-user-id` (and optionally `x-user-name`). Server middleware resolves/creates the user and sets `req.userId`.

**Files:** `server/src/db/schema.sql` (+ migration), `server/src/db/dal.ts` (every query scoped by userId), all `server/src/routes/*` (read `req.userId`), `server/src/middleware/user.ts`, `client/src/api.ts` (send headers), `client/src/identity.ts`, tests.

- [ ] `users` table: `id TEXT PRIMARY KEY, name TEXT, created_at TEXT DEFAULT (datetime('now'))`.
- [ ] Add `user_id TEXT` to `sessions`, `vocab`, `error_tally`, and the sentence-lab tables. Change uniqueness/PKs:
  - `vocab`: `UNIQUE(normalized)` -> `UNIQUE(user_id, normalized)`.
  - `error_tally`: PK `error_type` -> composite PK `(user_id, error_type)`.
  - `annotations` scope via `JOIN sessions ON sessions.id = annotations.session_id WHERE sessions.user_id = ?` (no direct column needed).
- [ ] Migration for existing local rows: assign a default user (`'local'`) so the developer's current data still works. Fresh prod DB starts empty.
- [ ] DAL: thread `userId` through EVERY read/write (`upsertVocab`, `getPrimeCandidates`, `getPrimeCandidatePool`, `recordErrors`, `decrementErrors`, `getTallies`, `getMistakeLog`, `getMistakeRanking`, `recordParagraphResult`, `getDailyMistakeCounts`, `getMistakeTrend`, `getVocabList`, `getVocabCount`, `getActivationStats`, sentence-lab fns, sessions). Every WHERE filters by `user_id`; every INSERT sets it.
- [ ] `middleware/user.ts`: read `x-user-id` (required for `/api` except the access-gate check); upsert into `users`; set `req.userId`. Reject missing id with 400.
- [ ] Client `identity.ts`: get-or-create `idiomate_uid`; a one-time name prompt; expose the id/name. `api.ts`: attach `x-user-id`/`x-user-name` to every request.
- [ ] Tests: two different `userId`s do not see each other's vocab/tallies; `recordParagraphResult` scopes to the user; ranking/prime are per-user.
